## 4. 你怎么写

两条路，选一条：

1. **PR**：fork 本仓，在 `main` 上开分支写 `20-共创-C线/inbox/task-*.md`，提 PR。执行端收到通知后拉到本地执行。
2. **协作权限**：把你在 GitHub 的账号给我，我加为 collaborator，你直接 push 到 `inbox/`。

没有第三种，`outbox` 与 `data` 只由执行端写，避免双写冲突。

## 9 物理输入分工（2026-11-28 08:25，代码侧申报「按不了物理按键的 player」后确认）

| 环节 | 代码侧（DeepSeek） | 执行端（本机 / 豆包） |
| --- | --- | --- |
| 代码与补丁 | 写 diff、注明行号、给回滚方式 | 只应用授权的那一处，改前备份 `.gN-orig` |
| 输入计划 | 给**有序键列表**（键名 + 每步间隔 ms + 允许重复次数）与每步之后的**可观测判据**（`draws` 区间 / 窗口标题 / `Ms` 区间） | 在真机按键（手柄或键盘），每步截一张图 |
| 不可替代的部分 | — | **物理按键、手柄热插拔、窗口聚焦、真机截图**：代码侧无输入设备，一律由执行端做 |
| 数字 | 只判读，不改判据 | 只报数，不判读 |
| 产物 | `inbox/task-*.md` | `outbox/r02-*.md` + csv 追加行 |

三条已验事实，写进分工理由，避免再试：

| 事实 | 出处 |
| --- | --- |
| 原始 release 包的 `VICTORY_KEYS` 无效（g2 解 `diagnostics` 门控后才生效） | `outbox` g2 记录 |
| 虚拟键 `Down/Enter` 不破 37-draw 卡点，喂存档才进世界 | g3 记录（S3b 路线） |
| 预热 25,985 shader 不解黑屏 | 早期实验 |

结论：**虚拟键脚本能改状态，不能替代人手上的那几下**；凡是要「看着画面按」的步骤，任务单里必须写成执行端动作，不能写成代码侧动作。
