# C 线协作协议（DeepSeek × 本机执行端）

## 1 角色边界

| 线 | 谁 | 拿到什么 | 交出什么 | 绝不碰 |
| --- | --- | --- | --- | --- |
| 推理线 | DeepSeek | 只读 `round-NN\A-任务简报-*.md` 里的源码片段、约束、验收标准 | unified diff、默认值影响矩阵、验证命令、回滚方式 | 构建、跑分、改本机文件 |
| 执行线 | 本机执行端（我） | 全部文件系统、PowerShell、`victory.exe`、`bench.ps1` | 补丁落地后的代码、`data\bench.csv` 新行、卡内账本摘录 | 不替推理线改设计，不把未验证的结论写成"已生效" |

两条线**同时跑**：推理线在设计 `round-01` 的补丁时，执行线已经在自己那条上跑环境变量 A/B（`round-01\B-我的实测计划.md`），互不阻塞。同步点只有两个：开工时读简报，收工时写回收记录。

## 2 一轮的形状

```
20-共创-C线\
  round-01\
    A-任务简报-显存预算.md      ← 给 DeepSeek 的输入（源码片段 + 约束 + 验收）
    B-我的实测计划.md          ← 执行线这轮自己做什么、测得什么
    C-回收记录.md              ← 补丁回来后：改了什么、实测多少、下一轮提示
```

执行顺序：A 由我写 → 你复制给 DeepSeek → 它回文本 → 我按 diff 落地、`cargo build`、`bench.ps1` 180 秒 → 结果写进 C → 你复制 C 给它 → 开 round-02。

## 3 交换格式（硬性）

推理线每条方案必须给这五段，缺任何一段执行线直接退回：

1. `诊断`：一句话说清为什么现在的默认值在这台机器上不自洽。
2. `patch`：对给定片段可套用的 `git diff` 格式；函数体必须完整，不许省略、不许 TODO。
3. `影响矩阵`：≥10 GB 卡 / 8 GB 卡 / `video_memory()` 返回 `None` 三种情况下的行为变化。
4. `验证`：给出观测点和判据（例如"卡内 used 应落在 budget 的 85–92%"），并说明用哪条日志行确认。
5. `回滚`：一行说明改哪个环境变量或还原哪个函数即可回退。

## 4 禁止项（会直接破坏部署）

| 禁止 | 原因 |
| --- | --- |
| 改 `crates/victory-core/src/policy.rs` 的 `ensure_outside_repo` | 仓库的资产边界，改了缓存就可能写进仓库 |
| 改 `rust-toolchain.toml` | `victory-gpu/build.rs` 把它算进 `VICTORY_TRANSLATOR` 指纹，25,756 个着色器全部失效 |
| `panic = "abort"` | `list/thin.rs:318` 依赖 `catch_unwind` 兜列表翻译线程 |
| 新增 crate 依赖 | 这个 fork 的依赖表锁在 `Cargo.lock`，加依赖要连带改锁文件与缓存指纹 |
| 把 "建议" 写成 "已改" | 执行线只认 diff + 实测，不认推测 |

## 5 交接质量要求

- 简报里的每个源码片段都带 `文件:行`，推理线引用时必须原样引用，便于执行线核对。
- 执行线回填的实测必须带取样条件（时长、场景、环境变量全集、机器状态），否则数据不可比。
- 一轮只改一件事。`round-01` 只碰显存预算的三个函数，线程与编译优化留到后续轮次。
