## 目标

回滚版 vs 基线的 A/B：两组各 200 s，同一套环境变量（`-Profile fork`），拿到 `world_samples / world_median_ms / max_draws / max_priv_gb / min_commit_free_gb` 与逐样本表，用来判定 round-01 的「+14.4% 帧时间 / +2.1 GB 提交」是否随回滚消失。

> 取代 `inbox\_superseded\task-20261126-2157-02.md`。前置：`r02-a1` EXIT=0，且本任务回填里复述的 SHA256 与 `r02-a1` 一致（否则等于又跑了旧 exe，本任务作废）。

## 命令

```powershell
# 0) 版本确认：把这里的 SHA256 与 r02-a1 回填比对，不一致就直接停
"exe_written=" + (Get-Item '<ROOT>\cool_fox\cool_fox-main\target\release\victory.exe').LastWriteTime.ToString('yyyy-MM-dd HH:mm:ss')
"SHA256=" + (Get-FileHash '<ROOT>\cool_fox\cool_fox-main\target\release\victory.exe' -Algorithm SHA256).Hash

# 1) 额度守卫：Commit Free 低于 6 GB 不启动（通道说明 §硬边界）
$c = (Get-Counter '\Memory\Commit Limit','\Memory\Committed Bytes' -SampleInterval 1 -MaxSamples 1).CounterSamples
$limit = ($c | Where-Object Path -match 'commit limit').CookedValue / 1GB
$used  = ($c | Where-Object Path -match 'committed bytes').CookedValue / 1GB
$free  = [math]::Round($limit - $used, 2)
"commit_limit_gb=$([math]::Round($limit,2)) commit_used_gb=$([math]::Round($used,2)) commit_free_gb=$free"

if ($free -lt 6) {
  "SKIP_BENCH: commit_free ${free} GB < 6 GB — 等页面文件扩到 >=48 GB 后重投本任务"
} else {
  Get-Process | Where-Object { $_.ProcessName -match '^victory' } | Stop-Process -Force -ErrorAction SilentlyContinue
  Start-Sleep 3
  cd <ROOT>\cool_fox-优化方案

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\13-bench-ab.ps1 `
    -Label R2-A2-baseline -Exe "<ROOT>\cool_fox\cool_fox-main\target\release\victory-baseline.exe" -Seconds 200 -Profile fork
  Get-Process | Where-Object { $_.ProcessName -match '^victory' } | Stop-Process -Force -ErrorAction SilentlyContinue
  Start-Sleep 5

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\13-bench-ab.ps1 `
    -Label R2-B-reverted -Exe "<ROOT>\cool_fox\cool_fox-main\target\release\victory.exe" -Seconds 200 -Profile fork
  Get-Process | Where-Object { $_.ProcessName -match '^victory' } | Stop-Process -Force -ErrorAction SilentlyContinue

  Get-Content .\data\bench.csv -Tail 3
}
```

## 验收标准

回填必须包含三样，缺一即 P1 打回：

1. `data\bench.csv` 新增两行**原文**（`R2-A2-baseline`、`R2-B-reverted`）；
2. 两次运行的**逐样本表原文**（`T / Fps / Ms / Draws / PrivGB / RssGB / FreeGB / CommitFreeGB`）；
3. 守卫行原文（`commit_limit_gb=… commit_free_gb=…`）与 `SHA256=` 行。

判读阈值（执行侧**只报数、不判读**；判读由代码侧做）：

| 指标 | 阈值 | 不满足时回填怎么写 |
| --- | --- | --- |
| `world_samples` | ≥ 8 | 写「本组作废：world_samples=N」，不得写"有效" |
| `max_draws` | > 1000 | 写「未进世界」，不得给帧时间结论 |
| `commit_free_gb` | ≥ 6（跑前） | 打 `SKIP_BENCH`，不得跑 |

## 禁止事项

1. **不得改写任何数字**：`ms` 不得换算成 `s`；`max_priv_gb` 不得四舍五入到整数；`bench.csv` 里的值不得手抄改写，只能整行粘贴。
2. **不得改变论证方向**：回填只允许写「本组 N 条世界样本、中位 X ms、峰值 Y GB」这类纯观测句；不得写"改善/持平/略有提升"之类判断（判读权在代码侧）。
3. **不得自行补充未经核实的结论**：不得解释为什么快/慢（页面调度、显存、驱动、WARP 均不得写进回填的结论段）。
4. 不得并发跑两局、不得在跑分期间启动第二个标题进程、不得边跑边构建。
5. `data\bench.csv` **只能追加**，不得修改或删除已有行（已有 `A-baseline` / `F-*` 行是历史证据）。
6. 收尾一律按映像名（`Get-Process -Name victory* | Stop-Process -Force`），不得用 pid。
7. 不得为了"凑样本"延长 `-Seconds` 或改 `13-bench-ab.ps1` 的采样逻辑。

## 失败时回填什么

- `SKIP_BENCH` → 原文回填，不跑。
- 崩溃 / 超时 / 空日志 → 该次 `data\run-<label>-*.log` 与 `*.err.log` 最后 20 行 + `Get-Process victory*` 结果。
- 出现两份以上 `victory*` 进程 → 先清理再回填「异常」段说明，不得带着残留进程出数。
