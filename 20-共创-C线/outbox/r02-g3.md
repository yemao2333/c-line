## 异常清单（本轮新增，只报事实）

### 1. 0 字节 `telemetrycache.dat` → 读档 1 秒退

`fork-eval-data\7952987A\temp\telemetrycache.dat` 在 01:17:50 被写成 **0 字节**（原件已备份 `<ROOT>\fork-eval\telemetrycache-fork-zero-0117.bak`）。症状：`victory.exe` 起动 1 s 内退出，err 仅 174 B、只有一行 `refused dll="rpcrt4.dll"`，标题不出现。

处置：把 `coolfox-data` 的 2,097,152 B 版本补回该路径（不删不改其它文件）。补回后同一 exe 立即正常：t=65 s `478 draws`、t=70 s `1457 draws`。

### 2. 起动期随机崩：`0x80070057` / 描述符堆上限

多次起动在 1–5 s 内退出，err 中含：

```
WARN victory_gpu::pipeline::host: host pipeline refused error=参数错误。 (0x80070057) shaders=[compute 369cbe906ea72764]
WARN victory_gpu::descriptor::host: host view heap capped at 1000000; views past it read a null slot count=1245184
```

同一 exe、同一存档、同一 keys，**同一分钟内两次起动可一败一成**（01:39 attempt1 死、attempt2 活到 753 s 收尾）。故不归因于存档内容：fork 侧 v88 三文件 mtime/长度与我们完全一致（2012 / 296 / 58，11-27 14:52:55），未被我方覆盖。

### 3. `bench-fork.ps1` 的 PID 跟踪会断

标题会 re-exec / 派生，`Get-Process -Id $p.Id` 拿不到新实例 → 循环 break、落 0–1 样本行、并在收尾时漏杀（`leftover` 后查为 0 但进程仍在）。本轮临时副本 `bench-fork-watch.ps1`（8,605 B）**只改这一处**：按映像名 `^victory` 取带 `draws/frame` 标题的那个；判据、filter、csv 列序、`world_from` 逻辑一字未动。

### 4. 长任务被工具运行时回收

`Start-Process pwsh -File bench-fork.ps1` 分离出去的子解释器在父调用返回后被回收（表现为脚本起窗口后秒退、err 空）。最终改为「一局起窗口 → 分段在工具调用里按 5 s 采样写 tsv → 收尾按同口径算」的三段式，采样间隔保持 5 s。
